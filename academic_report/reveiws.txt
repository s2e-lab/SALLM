Reviewer 1

The paper “Multi-Sallm: A Multilingual Security Assessment of Generated Code” proposes a framework to evaluate the security correctness of code generated by 4 LLM models with i) a dataset of Python prompts, ii) a static/CodeQL-based technique and a dynamic/unit test-based technique to assess code security, and iii) two new security metrics vulnerable@k and security@k. 

It is in fact very important to be able to guarantee the security aspect of LLM-generated code since a vulnerable code can be exploited by attackers, impacting the safety and security of systems. The generated code should not only be compiled and executed following its functional specification but also be secured. The objectives of the paper are relevant, but the methodology has several important drawbacks that are detailed as follows. 
I summarize the major issues in the following:

- The multilingual translation with 23 different prompting languages does not bring a substantial value added to the work, as their relevance to the work is not clear, while the experimental results do not show significant differences among the different languages (e.g., in Figure 4, the 23 charts are very similar). It would be more relevant, instead, to have different programming languages other than Python. It will be more challenging to measure the security of code with typed and memory unsafe languages, such as as C and C++, with various and complex memory errors, and also with safer programming languages such as Java or Rust.
- A question that is not addressed concerns the functional correctness of unsecured code (containing vulnerabilities or run-time errors) because in that case the behavior is not well-defined.
- Concerning the experimentation, study on the scalability of the approach is limited due to the limited size of the dataset (only 92 code snippets, which are not representative enough), the fact that unit tests were created manually, as well as the prompts.
- The metrics are too simple, especially the security@k metric which is not giving additional insights
- There is no information about the CWE coverage (number of treated CWEs vs total of CWEs for Python code)

Reviewer 2


Summary:
The authors proposed the MULTI-SALLM framework to address the critical issue of lacking systematic multilingual security evaluation benchmarks in the current LLM code generation domain. They constructed a security-centric prompt dataset covering 23 languages, designed novel security evaluation metrics (secure@k and vulnerable@k), and developed an automated evaluation framework combining static and dynamic analysis. The paper is well structured and easy to follow.

Strengths:
- The topic is interesting and important.
- The framework design is comprehensive, involving the construction of multilingual datasets, static analysis and dynamic evaluation techniques, and the design of novel security metrics. 
- The empirical study selected both open-source and closed-source LLMs, controlled variables such as temperature and k-value, and employed a multidimensional evaluation approach. 

Weaknesses:
- Limited evaluation using only CodeQL.
- Weak dataset with few real examples and only Python support.
- Multilingual assessment lacks human validation.
- Insufficient scenario coverage due to very few collected code snippets.

Detailed comments:
Static evaluation depends solely on CodeQL without cross-validation using other mainstream static analysis tools (e.g., Bandit), and the dynamic evaluation test cases are limited to known CWE vulnerabilities without adversarial scenarios.

The dataset would be more representative if code snippets from real GitHub projects were incorporated.

Although multilingual support uses back-translation and BERTScore, the lack of human evaluation suggests that small-scale manual quality checks should be added.

The dataset has major limitations, including support only for Python and very limited real-world snippet coverage (e.g., only 13 valid Stack Overflow samples), restricting cross-language generalizability and scenario diversity.

Reviewer 3

SUMMARY: 

- In this paper, the authors developed Multi-Sallm, a benchmarking framework to systematically evaluate the ability of large language models (LLMs) to generate secure code. There are three main components, namely (i) a dataset of security-focused Python prompts translated into 23 natural languages; (ii) configurable assessment techniques for analyzing generated code; and (iii) new metrics to evaluate models from the perspective of secure code generation.

- Overall, I think the topic addressed in this paper is timely and highly relevant, given the proliferation of LLMs and their applications in Software Engineering. As developers are using LLMs to generate code in the daily routine, a tool to test the security of the resulting code is highly important. 

- I was among the reviewers of the accepted workshop paper, and thus I know pretty well the contributions of the original work. I appreciate that the authors put a subsection to distinguish the current paper with the previous one.


Strengths:
+ The topic is timely relevant, and worth investigating.
+ There is a replication package with code and data available.
+ The proposed approach has been evaluated with four LLMs.


Weaknesses:

- The association with SOTA is unclear.
- The delta with the workshop paper needs further clarifications.


DETAILED COMMENTS:

- In the Abstract section, it is necessary to provide a brief summary of the findings (Experimental results, comparison with baselines, etc.). Currently, when reading the abstract, it is not clear what the contributions of the work are, as well as how it is related to state-of-the-art research.

- To guide the presetation, I think it makes sense to add a motivating example to illustrate the applicability of Multi-Sallm in a real-world scenario.

- There is Section 1.1., but no Section 1.2. I suggest the authors add another subsection, or remove the heading Section 1.1.

- The Related Work section is too short, and it does not associate well the submitted work with state of the art research in the domain. I can see that there are various papers about security testing of AI generated code, and thus I think it is necessary to distinguish the current paper from existing work. At least, there is the following paper: "DeVAIC: A tool for security assessment of AI-generated code" (https://www.sciencedirect.com/science/article/pii/S0950584924001770), and it is highly advisable to relate Multi-Sallm to DeVAIC.

- An important aspect is the delta of this work compared to that of the workshop paper. I think it is crucial to compare and contrast this in the Results section.


MINOR COMMENTS:

- AUSE imposes the author-based citation style (not numbers), please consult a published paper for more details.

- Figures 4--9 are pretty small and unreadable, please consider enlarging them all.

- Page 12: "When an LLM generate code from [...]" --> "When an LLM generates code from [...]"
